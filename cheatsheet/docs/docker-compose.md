# Docker compose

[Ссылка на курс](https://slurm.io/docker){ .md-button .md-button--primary }

`Docker Compose` — это инструмент для запуска сложных приложений, которые состоят из нескольких контейнеров, одной командой.

Compose управляет сервисами, сетями и томами в одном файле конфигурации YAML.

Compose полезен при любом сценарии: при запуске тестовых окружений, разработке и тестировании как небольших приложений, так и производственных сред.


## Пример compose из урока
```
services:
 web:
    image: nginx:latest
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html
    networks:
      - webnet


  app:
    image: my-app:latest
    build:
      context: ./app
    ports:
      - "5000:5000"
    environment:
      - ENV=production
    networks:
      - webnet
    depends_on:
      - db


  db:
    image: postgres:latest
    environment:
      POSTGRES_DB: mydatabase
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
    volumes:
      - db-data:/var/lib/postgresql/data
    networks:
      - webnet


networks:
  webnet:


volumes:
  db-data:
```


## Описание compose


`version: '3.8'` — версия, в последних версиях Docker её можно не указывать. (В интернете ещё можно найти случаи с указанием версии.)
`services:` — основной раздел, в котором описываются контейнеры (или сервисы), которые будут развёрнуты.
`web:` — имя сервиса, которое будет использоваться для ссылки на этот контейнер. 
`image: nginx:latest` указывает образ Docker, который будет использоваться для создания контейнера. Здесь используется официальный образ nginx с тегом latest, который означает последнюю версию.
```
ports:
  - "8080:80"
```
Определяет правила проброса портов. Здесь порт 8080 на хосте мапируется на порт 80 контейнера, что позволяет получить доступ к Nginx через порт 8080 на хосте.
```
volumes:
  - ./html:/usr/share/nginx/html
```
Определяет монтирование директорий или файлов. Здесь локальная директория ./html на хосте монтируется в директорию /usr/share/nginx/html контейнера, что позволяет изменять содержимое веб-страницы без перезапуска контейнера.
```
networks:
  - webnet
```
Указывает, к каким сетям подключается сервис. В данном случае сервис подключается к сети webnet.


`app:`
Имя другого сервиса, в данном случае приложения. 
`image: my-app:latest` Образ Docker для приложения. Используется образ my-app с тегом latest. 
```
build:
  context: ./app
```
Указывает на необходимость сборки образа из локального контекста. context: ./app означает, что Dockerfile находится в директории ./app.
В данном случае указывается не образ, а директория для сборки.
```
ports:
- "5000:5000"
```
Определяет правила проброса портов. Здесь порт 5000 на хосте мапируется на порт 5000 контейнера.
```
environment:
  - ENV=production
```
Определяет переменные окружения для контейнера. Здесь устанавливается переменная окружения.
>один из способов обозначения


```
networks:
  - webnet
```
Подключается к сети webnet.
```
depends_on:
  - db
```
Указывает, что этот сервис зависит от другого сервиса. Здесь указывается, что сервис `app` должен запускаться после сервиса `db`.


`db:` Имя сервиса базы данных 
`image: postgres:latest` Определяет Docker-образ для базы данных `PostgreSQL` с тегом `latest`. 
```
environment:
  POSTGRES_DB: mydatabase
  POSTGRES_USER: user
  POSTGRES_PASSWORD: password
```
Устанавливает переменные окружения для конфигурации базы данных PostgreSQL. Здесь создаётся база данных mydatabase, устанавливается пользователь user и пароль password.
>другой способ обозначения


```
volumes:
  - db-data:/var/lib/postgresql/data
```
Монтирует том db-data для хранения данных PostgreSQL. Это позволяет сохранить данные, даже если контейнер перезапустится или удалится.
```
networks:
  - webnet
```


```
networks:
  webnet:
```
Определяет пользовательские сети. В данном случае создается сеть webnet, которая будет использоваться сервисами.
```
volumes:
  db-data:
```
Определяет пользовательские тома. Создаётся том db-data, который будет использоваться для хранения данных PostgreSQL.
